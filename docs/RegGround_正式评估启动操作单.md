## 第 1 步 · 补数据(改 spike 脚本,~半小时)

### 1a. 补"各 scenario 准入后独立场景数"列

- 数据源:spike 已有的每帧记录 `(frame_token, scene_token, scenario_type, admitted)`。
- 计算:`admitted=True` 过滤后,按 scenario 分组数 `scene_token` 去重数。
- **同时输出配对总量**:准入后 `(scene_token, scenario_type)` 去重配对数——这是"普查规模",第 2 步列表长度的基准。
- 注意:一个场景可在多层各计一个单元(行人帧 + 红灯帧 = 两个单元),各层场景数之和 > 全局 207 **不是 bug**。

**验收**:新列存在;每层满足 `准入场景数 ≤ 该层 unique scenes`;配对总量已打印。

### 1b. 补灯态来源分布

- 聚合 scene_facts 里的 `traffic_light_status_source`,重点报 `none` 占比。
- 若 red_light 分类本身依赖灯态存在 → none 率恒 0 是"由构造保证",不是没问题:论文覆盖范围须写"限于 DriveLM 提及灯态的帧",此分布即证据。

### 1c. 修报告模板

- "决策提示"小节为空、fallback 提示掉在 token 列表之后 → 修拼接顺序。
- token 列表升级为**带元数据的表**:`token / scene / scenario / horizon 位移`(第 4 步冻结审阅用)。

## 第 2 步 · 重生成评估集(改选择逻辑,~半小时)

### 2a. 每(场景 × scenario)单元取一帧

- 分组:准入帧按 `(scene_token, scenario_type)`。
- 组内选择:**horizon 内 ego 位移最大**的帧(接近帧,决策仍在进行——scene-0757 里的 record 6,而非蠕行/等待帧)。
- 平手打破(确定性):时间戳早者 → token 字典序。
- **选择全程确定性,无随机成分**——seed 42 降为备用(仅未来需子抽样时启用),报告里写明这一点,可复现性主张更强。
- 已知简化写进局限性:一场景内两次独立同类事件会被折叠为一帧,接受。

### 2b. 排除 mini 场景(开发集污染)

- 从本地 `v1.0-mini/scene.json` 读出 **10 个 scene_token**,在选择**之前**从候选池过滤。
- **按场景排,不按帧排**(mini 帧是 trainval 同场景帧的子集,按帧排会漏)。
- 排除理由写进报告:"10 个场景为开发集,谓词、prompt、阈值、人工审计均在其上迭代"。
- 已证实混入:scene-0757(`e122a34e…` 在 264 列表中);其余 9 个无法按帧反查,必须按场景清单排。

### 2c. 重生成 + 自检

**验收(四条全过)**:
1. 列表长度 == 1a 配对总量 − mini 涉及单元数;
2. 任一 token 的 scene ∉ mini 清单;
3. 每个准入配对恰好出现一次;
4. **连跑两遍,输出逐字节一致**(确定性直接证明)。

## 第 4 步 · 冻结:从"一个列表"到"正式评估集"

建 `eval_set_v1.json`(或 yaml),**五件套**:
1. 带元数据的 token 表(1c 格式);
2. 选择规则文字描述(2a,含确定性声明);
3. 排除清单:10 个 mini 场景 + 理由;
4. 第 3 步薄层决策原文;
5. 生成脚本的 git commit + spike 报告引用。

**纪律(与 experiment.yaml protocol_id / config_version 同一哲学)**:
- commit 进 git,**从此不可变**;要改 → 升 v2 + 写明理由;
- 主实验、消融、人工外部审计**共用此集合**,漂移一次则跨 run 比较全部作废;
- 冻结同时防的是自己:正式结果出来后"这个场景很怪要不去掉"的手,现在捆住;
- **正式 run 从此文件加载集合**(不现场重生成),run manifest 记录 eval_set 版本/哈希——每份输出可回答"跑在哪个集合上"。

## 第 5 步 · 启动检查 → 试跑 → 全量

### 5a. 启动检查清单(逐项过,一项不过不点火)

- [ ] **clean git**:全部提交,`git status` 干净——论文引用的 run,git_commit 必须对应真实代码状态(manifest 决策中唯一保留的硬要求);
- [ ] **谓词审计交卷**:15/15 一致已有;**补 6 张图确认完成**——records 6/8 的 conservative / suboptimal / hard_case,尤其 record 6 traj_f(唯一谓词弃权样本);
- [ ] **补丁 A**:顶层 `candidate_verdict_accuracy` 已删或已 gate 到 LLM 层;
- [ ] **补丁 B**:uncertain 三条规则 + 回归测试全绿(**含孪生轨迹 tie 用例**——该修复至今未被真实数据验证,仅测试兜底);
- [ ] **eval_set_v1 已冻结**(第 4 步产物)。
- [ ] **候选物理闸门**:记录 `drivable_area` 校验通过数/校验候选数；只有正式结果确为全通过时，论文才表述“100% 候选位于可行驶区域内”。
- [ ] **W6 答辩案例**:联调时收集 1 个“GT 被 vetoed、保守变体胜出”的完整案例，保留轨迹图、特征、规则命中和最终排序。

### 5b. 试跑(10 个场景,~7 分钟)

- 目的:抓分布外工程炸弹(几百个陌生路口——地图层缺失、冲突区构造 NaN 之类),让它在第 10 个场景爆而不是第 200 个。
- **纪律:只看 ok / error / 异常栈,不看 benchmark_evaluation 块**——这不是偷看结果的窗口。
- 试跑干净 → 点火全量。

### 5c. 全量

- 规模预期:~250 单元 × ~40s 串行 ≈ **3 小时**,挂一晚绰绰有余;
- 盯 telemetry:429 计数、degraded 计数(mini 上均为 0,250 场景连续调用是另一个量级);
- **中途发现 bug 铁律:修 → 提交 → 整个 run 从头重跑**。半新半旧代码的混合 run 不可用——试跑的意义就是把重跑代价压在 10 个场景;
- 跑完:人工外部审计抽样(LLM 层候选 + 谓词子样本)直接取自本次输出;分析按第 1 步已就位的分层口径走。

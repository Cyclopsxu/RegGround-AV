## 1. 定位与贡献(Introduction / Contribution)

### 1.1 一句话定位
一个**法规接地的可解释轨迹偏好标注系统**:给定路口场景下的多条候选轨迹,系统检索相关交通法规,对每条候选做出**可审计的**合规性判断与偏好排序;该标签可用于自动驾驶模型的偏好后训练(RLAIF 式)。

> 可解释选择是**机制**,偏好打标是**用途**:可审计合规判断(机制)→ 偏好标签(产物)→ 模型后训练信号(用途)。

### 1.2 核心叙事
**"Regulation-Grounded RLAIF for Autonomous Driving"**。法规图谱在叙事上类比 Constitutional AI 的 "constitution"——一部可查询的**"驾驶宪法"**。

一句话卖点:*"不同于自由生成解释的 LLM 裁判,我们的选择与解释都锚定在可审计的法规图谱上,从而为安全攸关场景提供可信、可溯源的偏好标签。"*

### 1.3 贡献清单(建议措辞)
1. 提出法规接地的自动偏好标注范式,填补"依赖人类标签"与"自由 LLM 裁判"之间的空白;
2. 一套 graph-RAG 法规接地机制,使每个判断可追溯到具体法条(`cited_rule_ids`);
3. 一套**让自动化评估本身可信**的方法学(分层报告防循环、预注册、盲审谓词、确定性冻结、失败可审计)——这套方法学可迁移到任何"知识接地的自动评估"场景;
4. 在 nuScenes + DriveLM 上的概念验证:系统不仅判定更准,且能正确引用违反的法条,这是自由 LLM 裁判不具备的。

**[来源:早期设计 + 本轮]** **[强度:★★★ 全篇骨架]**

## 3. 方法与架构(Method)

### 3.1 系统链路
```
真实轨迹 → 定向违规扰动器 → 候选组(含自动GT)
场景 → 场景编码器 → 结构化要素 + 简短自然语言摘要
      → graph-RAG 检索器(按场景要素召回相关法条)
      → 分层判定:几何谓词 → 规则引擎(确定性) → LLM(仅模糊候选)
      → 每候选:verdict + cited_rule_ids + rationale;偏好排序
      → 结构化记录(输入+检索依据+判定+元数据,全程 provenance)
```

### 3.2 法规知识图谱(手工构建,刻意小,≤10 条)
节点:`Rule`(id/文本/类别 signal|yield/适用条件)、`Condition`(触发条件,如"红灯相位")、`Behavior`(受规制行为,如"越过停止线")。
关系:`Rule --APPLIES_WHEN--> Condition`、`Rule --PROHIBITS/REQUIRES--> Behavior`、`Condition --CO_OCCURS--> Condition`。
每条 Rule 有稳定 `rule_id`,供 LLM 引用、供评估与 GT 的 `violated_rule_id` 对齐。

> **graph-RAG 相对纯向量 RAG 的卖点**:法条与触发条件、受规制行为间有显式关系,可按场景要素**精准召回**而非语义相似度模糊匹配——论文里要讲清这个不可替代性。

### 3.3 LLM 合规判断器的关键约束
Prompt 分层:任务说明 → 法条层(检索结果,含 rule_id)→ 场景层 → 候选层 → 输出约束层。
**核心抑制幻觉的约束:"只能依据给定法条判断,不得援引未提供的法条"**;输出必须带 `cited_rule_ids`,使每个判断可追溯可审计。这是与"自由生成 LLM 裁判"的关键区别。

### 3.4 定向违规扰动器(数据生成关键,省标注核心)
真实轨迹视为合规基准;**定向**(非随机)扰动生成针对特定法规的违规候选,生成时**自动记录违反了哪条法规**,该记录即 GT。

| 违规类型 | 法条类别 | 扰动方式 |
|----------|----------|----------|
| 闯红灯 | 信号灯 | 红灯相位下,停车/减速轨迹改为穿越停止线继续行驶 |
| 黄灯抢行 | 信号灯 | 黄灯相位下本应减速停车,改为加速通过 |
| 该让未让 | 让行 | 存在优先方时本应等待,改为抢先通过 |

**为什么定向而非随机**:随机扰动会造出"全合规"或"全明显违规"的无区分度候选组;定向保证每组既有合规项又有针对特定法条的明确违规项,评估才有意义。GT 在扰动时确定,人工只需"核对"不需"从零判断",标注负担极低。

**[来源:早期设计]** **[强度:★★★ 方法主体]**

## 4. 评估设计(Evaluation)

### 4.1 三方一致性框架(轻量档,标签质量)
- (A) 本系统(法规接地)标签
- (B) 普通 LLM 裁判(无 RAG、自由判断)标签 —— 对照组
- (C) 人工核对标签(基于自动 GT 的人工确认)

除准确率外,专设**可审计性指标**:不光判对违规,还要**引对法条**——这是普通 LLM 裁判做不到的,是最能打的差异点。

### 4.2 评估集构造(本轮沉淀,方法学价值高)
- 数据:nuScenes v1.0-trainval + DriveLM-nuScenes,**Boston-seaport only**(新加坡左行交通与右行规则图语义冲突,永久排除——写进局限性,不是 fallback);
- 单位:**scene × scenario**,每单元取信息量最大的一帧(horizon 内 ego 位移最大),确定性选择、无随机;
- 准入:排除静止 ego(零信息)、排除 mini 开发集 10 个场景(防污染);
- 规模:约 259 单元。分层:pedestrian 121 / oncoming 52 / red_light 69 / yellow_light 12 / emergency 5(场景数)。

### 4.3 指标口径(本轮定稿,直接可写方法节)
- **主指标:illegal-chosen rate**(系统选中违规轨迹的比例,目标 0);
- gt-chosen / gt-top2 **降为参考指标**(合规候选间"最优"不唯一,GT 非唯一正解;红灯场景区分度天然低);
- 选中不可评分候选(hard_case/exclude)记 **unscorable 单列**,不计入失败分母;
- degraded / uncertain 率**如实分列报告**。

**[来源:早期设计(4.1) + 本轮(4.2/4.3)]** **[强度:★★★ 结果可信度地基]**

## 5. 方法学严谨性(本项目真正的护城河)——建议单列一节或贯穿方法/评估

> 这一节是本轮工程会话沉淀出来的,大多数同类论文没有,是审稿人挑不动、也最能体现"负责任的自动化评估"的部分。每一条都建议在论文里显式讲。

### 5.1 分层报告,规避循环论证 ★最重要
几何谓词**同时**生成 benchmark 的 `expected_verdict` 和驱动规则引擎判定 → "规则引擎层准确率 vs benchmark"是**自己对自己**(恒为 1.0,零信息)。
**解法**:verdict 指标分两层报告——规则引擎判定子集报"谓词 vs **人工**一致性"(人是外部效标);LLM 判定的模糊子集才报 vs benchmark 准确率(这才是对"法规接地裁判"的真评估)。
> 论文价值:主动暴露并解决"评估自证"陷阱,是方法学成熟度的直接体现。同一原理也适用于任何"用规则生成标签又用规则判定"的系统。

### 5.2 预注册薄层决策
emergency(n=5)、yellow_light(n=12)样本薄 → **在看到结果之前**决定其处置(emergency 降为定性案例研究不进聚合指标;yellow 作独立披露层、预声明不做显著性主张)。评估前决定叫预注册,评估后再决定叫挑数据。

### 5.3 盲审几何谓词,产出人工一致性
规则引擎承担约九成判定,判据是几何谓词;谓词又生成 benchmark 标签 → 唯一有效外部效标是**人眼看几何**。做法:可视化叠加图**不标谓词判定**、盲判、判完再 join 对比、每条不一致写归因。产出 `predicate_human_agreement`。通过线:可判定样本一致率 ≥95%,vetoed 分歧零容忍。
> 呼应一句可写进论文:自动系统的判据必须有人类外部效标背书,不能 AI 自己跟自己对答案。

### 5.4 确定性冻结与溯源链
评估集冻结为不可变版本,溯源五环环环相扣:
`eval_set(钉帧) → input_sha(钉数据) → 分类指纹(钉语义,启动时核对不符拒跑) → 双跑逐字节一致(钉生成) → clean git(钉代码)`。
> 这五环直接就是论文可复现性一节的骨架。

### 5.5 uncertain 的双重语义与"不可 p-hack"红线
- **语义 uncertain**(`decided_by: llm`,模型看了答"信息不足")= 一个判决,**永不重跑**(重跑到改口=给自己的裁判 p-hacking);
- **基础设施 uncertain**(`decided_by: fallback`,压根没得到回答)= 数据缺失,可补跑。
资格按 `decided_by` 字段代码强制,不留人为裁量。

### 5.6 fail-closed 与失败可审计(工程即方法学)
- degraded **标记而非静默吞掉**;uncertain **永不成为 chosen**;cleared=0 → `no_choosable_candidate` 而非硬选;
- 分布式 LLM 调用天然有 ~1% 失败率,正确姿势不是追求零失败,而是**失败可见、失败安全、失败率有验收线**;
- 候选级(非 stage 级)降级:一次调用失败只损失一条 uncertain,不连坐整单元;
- 清扫轮(deferred repair pass):主循环结束后只补跑基础设施失败的候选,吃掉 episode 型网络故障,全程留痕。
> 论文价值:把"LLM-in-the-loop 评估的可靠性工程"作为贡献的一部分,少见且扎实。

### 5.7 场景级去重,避免伪重复
早期 mini 上 5 个"红灯场景"实为同一次停车的 5 个 keyframe(effective n=1)。评估集以 scene×scenario 为单位、每单元一帧,论文 n 按**独立场景**口径报告。
> 一个诚实的小教训,写进方法节反而增信。

## 6. 局限性(Limitations)——主动写,别等审稿人戳

1. **概念验证范围**:仅路口信号灯 + 让行两类离散规则,单一法系;明确表述为 proof-of-concept。
2. **未做下游微调验证**:只做标签质量档,未拿标签训模型证明"开得更合规"(工作量与翻车风险,收尾作不背)。
3. **模态与几何多样性**:mini 谓词审计仅在单一路口几何上验证零偏移;几何多样性验证留给 trainval 外部审计。
4. **灯态覆盖**:红灯/黄灯层限于 DriveLM 提及灯态的帧(灯类分类与灯态存在严格绑定,可报覆盖数字为证)。
5. **薄层**:emergency(n=5)仅定性,yellow(n=12)不做显著性主张。
6. **托管模型漂移**:对话/判定跑在无 SLA 托管 API,provider 可能静默更新模型;需记录 model_id、报告 degraded 率,纵向可比性受此约束。
7. **单人自审 vs 正式外部审计**:当前谓词一致性为单人工程自审(解锁评估),论文正式的 predicate_human_agreement 需 2–3 人外部审计报 IAA。

**[来源:早期设计 + 本轮]** **[强度:★★ 必备,增信]**

## 7. 可复用抽象(可作为 discussion / 未来工作的一段)

本方法学可提炼为领域无关的骨架:**知识接地的自动化评估/反馈闭环**。
- `retrieve(context_features) -> knowledge_items`(驾驶:检索法条 / 教育:检索教学策略)
- `GroundedEvaluator.evaluate(target, knowledge) -> verdict + cited_evidence`(驾驶:判轨迹合规 / 教育:评对话认知水平)
- 领域决策外置为配置/知识库,骨架给默认值。

> 可在 discussion 里点一句:同一套"检索接地 + 可审计判定 + 分层可信评估"的方法,适用于金融、医疗、自动驾驶等受监管领域的 AI 决策审计需求。**但收尾论文不必把跨领域包装成主线**,点到为止即可。

**[来源:早期设计(与教育项目的复用讨论)]** **[强度:★ 加分项,勿喧宾夺主]**

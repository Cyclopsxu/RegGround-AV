# 2×2 消融实验 · 技术文档 v1.0

**RegGround-AV · GraphRAG × 引用回校验消融**

| 项目 | 内容 |
|---|---|
| 依据 | Layer 3 spec v3.0 §10.4;修订实现手册 v2.0 第五部分;影子评估线(disable_rule_engine 复用) |
| 运行时机 | 代码 + dry-run 现在完成;**正式运行等人工 gold 定稿后** |
| 运行范围 | 仅人工标注子集(gold 场景清单),不跑全量 |
| 冻结约束 | 生产系统、benchmark、盲标包不因本实验改动;本实验为纯评估臂 |

---

## 1. 目标

量化两个机制各自与联合的贡献:**GraphRAG 法规接地**(检索到的真实规则进入 prompt)与**引用回校验**(CitationValidator 拦截越界引用)。核心产出是四条件下的幻觉率、citation validity/accuracy、与人工 gold 的判定/偏好一致性对比——其中 Baseline(双关)的幻觉率是论文最重要的单一对比数字(架构文档预期 ≥20%)。

## 2. 条件矩阵

| 条件 | GraphRAG | 回校验 | 目的 |
|---|---|---|---|
| `full` | 开 | 开(enforce) | 完整系统 |
| `no_validation`(Ablation A) | 开 | 关(observe) | 接地单独能压多少幻觉 |
| `no_rag`(Ablation B) | 关 | 开(enforce,校验对象见 §5.2) | 拦截网单独能救多少 |
| `baseline` | 关 | 关(observe) | 自由 LLM 裁判 |

**统一设定:四条件全部 `disable_rule_engine=True`**(复用影子评估 flag)。理由:消融隔离的是 LLM 判定机制;规则引擎开启会让 full 条件的决定性候选被谓词截走,四条件的 LLM 比较面不对齐。报告显式声明该选择(生产系统含规则引擎,本实验测 LLM 环节)。

## 3. 输入与公平性约束

- 入参为**场景清单文件**(gold 定稿后冻结的子集清单),SHA-256 入 manifest;dry-run 用替代清单。
- 四条件严格同:模型/版本/thinking/温度(0.0/0.0/0.2)/超时/重试参数(冻结配置原样)、候选呈现顺序、**digest v_a 措辞**(消融变量只有 RAG 与校验,严禁夹带 v_b 措辞或其他改动)。
- 每条件独立输出目录与 JSONL,独立 manifest(条件 flag、全部 prompt SHA-256、场景清单哈希),永不混写。
- 四个 prompt 变体全部通过 LeakageGuard;条件间 prompt diff 逐条归档。

## 4. Prompt 设计

### 4.1 RAG 条件(full / no_validation)

生产 prompt 原样:场景要件(digest v_a)→ 可引用规则(检索结果)→ 候选特征。

### 4.2 no-RAG 条件(no_rag / baseline)

- 移除全部规则文本与 rule_id;digest、候选特征小节不变。
- 判定指令改为:"依据你所知的中国道路交通安全法及相关法规判定,并**必须**为每个判定引用具体法律条款(法律名称 + 条号),写入输出的 `cited_provisions` 字段"。
- **强制引用是本条件的关键**:不引用则幻觉不可测。结构化输出 schema 为 no-RAG 条件增加 `cited_provisions: list[str]` 字段;模型拒引时该判定计入"无引用"桶(见 §6 引用密度)。

## 5. 校验模式实现

### 5.1 observe 模式(no_validation / baseline)

CitationValidator 增加 `mode: Literal["enforce","observe"]`:

- observe 下不重试、不拦截、不抛异常;首发引用原样落盘并打 `citation_check: passed|violated` 标记;越界 rule_id / 幻觉条款流入 AuditLabel——**这正是被测对象**,下游组装代码不得因非法引用崩溃(强化现有模型的容错)。

### 5.2 enforce 模式下的 no_rag(Ablation B)

无检索集合时"回校验"校验什么:校验对象为**全量图谱规则的 code/法名条号集合**(而非本场景检索子集)——即"引用的条款是否真实存在于已审计法规库",不校验场景适用性。实现:引用抽取器(§6)解析 `cited_provisions`,与 rule_graph 的 code 表 + 法条别名表匹配;不匹配触发一次重试(与 enforce 语义一致)。该操作化在报告中显式定义。

### 5.3 首发引用全条件记录

enforce 条件也必须**额外记录首发引用**(修复前快照):首发 vs 终态之差 = 拦截层贡献,是 full vs no_validation 对比的内部佐证。

## 6. 引用抽取与幻觉指标(§10.3 口径,两轨)

| 轨 | 条件 | validity | accuracy |
|---|---|---|---|
| rule_id 轨 | full / no_validation | 机器判:rule_id ∈ 可引用集合(首发与终态分别报) | 对人工 gold(引用是否适用) |
| 自由文本轨 | no_rag / baseline | 引用抽取器解析"法名+条号"→ 人工评级:条款是否存在、内容是否如其所述 | 人工评级:是否适用本场景 |

- **引用抽取器**:从输出解析引用为结构化条目(原文、法名、条号),吐出**引用评级表**(条件 × 场景 × 引用 × 三个待人工评级列),随 gold 标注一并人工评级。
- `hallucination_rate = (invalid + inaccurate) / total_citations`,四条件同一公式。
- **引用密度**必报:每判定平均引用数 + 无引用判定占比——防止 baseline"少引用 = 少幻觉"的假象。

## 7. 指标计算模块(gold 到位后一键出)

逐条件输出:

- verdict vs 人工:Cohen's kappa(cleared/vetoed/uncertain 三类);
- 偏好对一致率、chosen vs 人工 top-1、Kendall's tau(与偏好工作簿 gold);
- citation validity(首发/终态)、citation accuracy、hallucination rate、引用密度;
- 弃权率、token、耗时、重试数。

报告要求:

- **配对呈现**:同场景四条件判定并排(逐场景明细表),对比结论基于配对计数而非仅边际率;
- 分层:scenario_type × difficulty;
- 小 n caveat 自动写入(子集 50–100 场,分层格会薄);
- 单次运行 + 判定方差 caveat(援引 `7dad` 教训,不做多次重复)。

## 9. Dry-run(现在完成)

`--dry-run` 模式:

- 假 gold(随机标注)+ 3–5 个场景 × 四条件全链路走通;
- 验证:observe 模式不崩、no-RAG 引用抽取器吐出评级表、指标脚本产出完整 metrics.json 与对照表、四 manifest 哈希齐全;
- dry-run 产物打 `DRY_RUN` 标记隔离存放,严禁与正式产物混淆。

## 10. 成本与断点

- 估算:80 场 × 4 条件,无规则引擎截流 → 全部候选走 LLM;约 6–10 小时、200–300 万 token;
- 断点续跑复用全量机制(幂等追加 + fsync);正式运行前核对 API 配额;
- 四条件可串行过夜跑,条件间不并发(避免限速互扰)。

## 补丁 A · 删除循环指标(P0,一行改动)

**问题**
summary 顶层 `candidate_verdict_accuracy: 1.0` 统计的 11 个候选全部由规则引擎判定;规则引擎与 benchmark 打标共用同一套谓词 → 该指标 = 谓词自己对自己,恒为 1.0,零信息。新的 `verdict_layers` 块在同一份 summary 里正确拒报了同一个数,新老口径互相矛盾。

**改动点**
- 删除顶层 `candidate_verdict_accuracy`;或改名为 `llm_layer_verdict_accuracy`,只统计 `decided_by=llm` 的候选(与 `verdict_layers.llm` 同源同值)。
- 规则层的效标位留空档,由补丁 C 的 `predicate_human_agreement` 填。

**验收断言**
- 重跑 mini:summary 中不存在任何"规则层 vs benchmark"的准确率数字;LLM 层准确率与 verdict_layers.llm 一致。

## 补丁 B · uncertain 政策焊死(P0,三条规则 + 回归测试)

**问题**
record 6 中 uncertain(traj_f)排在 cleared 之后、vetoed 之前,且未进 pairwise——本轮行为合理,但无法确认是规则保证还是巧合。危险边界:**若某场景 cleared 为零,"选排名最高的非 vetoed"逻辑会把 uncertain 盖成 chosen**——给一条"不知道合不合规"的轨迹发"最优"标签,混进下游偏好数据比漏判更糟。正式集场景更难、uncertain 更多,该边界必然出现。

**改动点(三条显式规则)**
1. uncertain **永不可**成为 `chosen_trajectory_id`;cleared 为零的场景置 `status/label = no_choosable_candidate`,单列统计,不硬选。
2. 排序位置固定:cleared 之后、vetoed 之前(现行为,升格为断言)。
3. uncertain 不进 pairwise(现行为,升格为断言;pairs 恒 = C(cleared, 2))。

**回归测试清单(与补丁 5 的测试批合并)**
- 构造 cleared=0 场景 → 断言 no_choosable_candidate,无 chosen;
- 构造 cleared/uncertain/vetoed 混合 → 断言排序分层与 pairwise 计数;
- **孪生轨迹 tie 用例**:两条舍入特征全同的候选 → 断言计入 tied_pairs_count 且 partial_reasons 含对应枚举(上轮修复因孪生场景被静止准入拦截而**从未被真实验证**,只有此测试兜底);
- summary 记账不变量:pairs = C(cleared,2) + cleared×vetoed(compliance 对)。

**验收断言**
- 测试全绿;mini 重跑行为不变(本轮行为即目标行为,只是从巧合变保证)。

## 补丁 C · 谓词人工审计操作规程(P0,正式评估前必须交卷)

> 目的:产出 `predicate_human_agreement`——规则层(当前承担 11/12 判定)唯一有效的外部效标。谓词 vs benchmark 是同源自证(补丁 A 已删),**人眼 vs 谓词才是检验**。

### C.1 可视化脚本(半天,审计的使能件)

每条候选一张鸟瞰 PNG:
- 轨迹航点,按速度着色(静止段一眼可辨);
- 冲突区多边形(停止线代理)+ 地图停止线(若有);
- ego 起点、朝向箭头、比例尺;
- **图上不含任何谓词输出**(entered_conflict_zone 等一律不标)——盲判前提;谓词值另存 sidecar 文件供 join。

### C.2 抽样(30–50 条,分层非随机)

| 层 | 内容 | 理由 |
|---|---|---|
| 必进 | record 6 traj_b(已结案,肉眼确认闭环)、全部 uncertain、全部 hard_case、全部 is_degenerate | 分歧和模糊处才是谓词的考场 |
| 必进 | 全部被 vetoed 的候选 | veto 盖 confidence 1.0 的章,错一条都不行 |
| 随机 | 常规 cleared 补足样本量 | 防"只审边界、漏系统性偏移" |

样本源:mini 现有候选 + trainval metadata 到位后补少量正式场景(谓词在新分布上的表现更有代表性)。

### C.3 盲判协议

逐张图回答固定三问(答案记表格,candidate_id + 三答):
1. 轨迹是否越过停止线(代理区)?——是 / 否 / **图上无法判断**
2. 越线前是否完整停车?——是 / 否 / NA / 无法判断
3. 按 R-SIG-01,该轨迹应判?——cleared / vetoed / uncertain

**纪律:全部判完再 join 谓词输出**(脚本自动对齐),先判后对,防锚定。单人自审的盲法就靠这个顺序保证。

### C.4 指标与归因

- `predicate_human_agreement` = 第 3 问的一致率(verdict 级),另分谓词报第 1/2 问 vs `entered_conflict_zone` / `stopped_before_zone` 的一致率;
- **每条不一致写归因**,三选一:谓词 bug / 冲突区代理几何偏移 / 本质模糊(应路由 uncertain);
- 人答"无法判断"而谓词给出了确定判定的候选 → 逐条审视:谓词是否越权,是否该收窄判定域;
- 发现代理偏移 → 修几何 → **bump predicate_version → 重推导 benchmark → 受影响样本复审**(谓词一动,打标全体跟着动,版本号是追溯锚)。

### C.5 通过标准与两段式定位

- 通过线:可判定样本一致率 **≥ 95%**;vetoed 分歧 **零容忍**(每条 root-cause 后才能进正式评估);
- **两段式诚实**:本次单人自审 = 工程验证,解锁 trainval;论文正式的 predicate_human_agreement 由补丁 6 的外部审计(2–3 人)顺带做谓词子样本并报 IAA。自审数字不冒充正式效标,论文方法节按此表述。

**验收断言**
- 产出审计表(逐条:人判 / 谓词判 / 一致 / 归因)+ 一致率数字;
- vetoed 层零未解释分歧;
- 若谓词修改:predicate_version 已 bump 且 benchmark 已重推导。

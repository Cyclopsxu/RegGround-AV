# 人工标注子集(盲标包 v1)修改意见

**对象**:`human_annotation_v1/`(blind_annotation_template.xlsx + README + 导出脚本)
**结论**:盲评隔离与抽样纪律已达标,可在完成下列修改后发放。修改项按优先级排列:P0 影响论文主指标,P1 影响标注质量,P2 为工程卫生。

---

## 定位确认

本包对应 Layer 3 spec §10.2「人工标注子集(50–100 keyframes)」。spec 要求标注四类内容:

| spec 要求 | 当前覆盖 | 支撑指标 |
|---|---|---|
| 哪些轨迹违规 | ✅ human_verdict | Cohen's kappa |
| 每条违规应引用的规则 | ✅ human_violated/applicable_rule_ids | citation accuracy |
| 哪条轨迹最优 | ❌ 未覆盖 | chosen vs 人工 top-1 一致率 |
| pairwise 偏好关系 | ❌ 未覆盖 | Kendall's tau、偏好一致率 |

后两项在"一场景一候选"设计下物理上不可标注,需按 P0-1 补齐。

---

## P0-1 补做场景级偏好工作簿(第二份表)

**问题**:每场景只呈现 1 条候选,标注者无从比较,导致 §10.5 的下游有效性 proxy(Kendall's tau、chosen 一致率、preference pairs 一致率)全部无法计算。这是系统"产出 RLAIF 偏好信号"定位的核心验证,不能缺。

**修改**:新增 `preference_annotation_template.xlsx`,设计要点:

- 抽样:从 120 个主样本场景中选 30–40 个,优先纳入「≥2 条候选被系统判 CLEARED」的场景(否则无排序可比);13 个可评分场景全部纳入。
- 行结构:一行一场景;并排列出该场景**全部候选**的匿名 ID + 特征摘要(复用现有 trajectory_summary 生成逻辑),候选呈现顺序按固定 seed 再次打乱,且与 verdict 表的呈现顺序不同。
- 标注项:`human_best_trajectory`(单选,可填 NONE 表示无可接受轨迹)、`human_ranking`(全排序,如 `traj_c>traj_a>traj_e`,允许并列用 `=`)、`human_confidence`、`human_reason`。
- 全排序可自动展开为全部 pairwise 对,无需让标注者逐对填写(30 场景 × C(4,2)≈180 对的逐对填写不现实,全排序是标准替代)。
- 隔离要求与 verdict 表一致:不显示系统 ranking/chosen、不显示 verdict 表中该场景抽到的是哪条候选。
- 两名标注者独立完成,揭盲后计算排序层 IAA(Kendall's tau between raters)。

## P0-2 说明页加入全量规则卡,允许标注"漏检规则"

**问题**:标注者只能看到 `retrieved_rules` 列(Layer 2 的检索结果),无法引用一条自己没见过的规则。citation accuracy 因此只能测 precision,Layer 2 的 recall 错误完全不可见。

**修改**:

- 在「标注说明」sheet 追加全量规则卡:全部 8–10 条规则的 `rule_id + 一句话描述 + hard/soft`,一屏可读。
- 说明中追加一条:「若你认为某条规则适用于当前场景但未出现在 retrieved_rules 列,请照规则卡填入 human_applicable_rule_ids,并在 notes 注明 `未检索到`」。
- 揭盲后即可分别计算 citation precision(检索规则中被人工确认适用的比例)与 citation recall(人工认为适用的规则中被检索到的比例)。

## P1-1 压力案例混洗进主样本

**问题**:20 个压力案例集中在 audit_121–140(override 案例位于第 129 行可证)。尾部聚集本身是信号,标注者可能对末段行为切换心态,污染压力案例的失败分析价值。

**修改**:导出脚本中将 140 行统一按现有 seed=42 的 SHA-256 排序混洗后再编号 audit_id;分组归属只保留在 `private/hidden_sidecar.jsonl`。改动约几行代码,重新生成即可(注意 README 已提示:重新生成前先确认没有已回收的标注结果)。

## P1-2 发放前完成回收校验脚本

**问题**:规则 ID 列为自由文本,回收时必然出现格式噪声(`R-YLD-1` vs `R-YLD-01`、中英文分号、空格);verdict 与 violated 列的一致性约束(cleared/uncertain 必须 NONE,vetoed 至少一条 hard rule)目前无机器校验。

**修改**:新增 `code/validate_returns.mjs`(或 py),校验项:

1. 行数 = 140,audit_id 集合与模板一致且顺序未变;
2. human_verdict ∈ {cleared, vetoed, uncertain},无空值;
3. rule ID 归一化后 ∈ 合法集合;分隔符统一为英文分号;
4. verdict–violated 一致性(同 VetoResult 的 validator 逻辑);
5. vetoed 行的 violated 规则必须为 hard;
6. confidence ∈ [1,5] 整数,reason 非空。

校验不通过的行生成退回清单,当场补标。此脚本与后续 IAA 计算共用解析层,属提前投资而非额外成本。

## P1-3 发放前跑 5–10 行校准轮

**问题**:两名标注者对 uncertain 门槛的理解差异会直接拖垮 kappa(uncertain 在本项目是敏感类目,系统侧已有 907 个)。

**修改**:主样本之外另抽 5–10 行(建议含 1 个临界减速、1 个 creeping、1 个明显违规、1 个明显通过),你与一名标注者各自独立标注 → 对分歧 → 把分歧案例的裁定标准写回说明页(判例式,如「冲突区内最低速度 < X m/s 且有行人 → 不足以 cleared」)→ 再正式发放。校准行不计入正式样本。

## P1-4 说明页补一行填好的示例

工作簿内无示范行,仅 README 有文字示例。在「标注说明」sheet 末尾加一行完整填写的虚构示例(标明"示例,勿计入"),展示 rule ID 格式、reason 的期望粒度。

## P2-1 可复现性锚点

导出依赖 Codex 工作区随附的 `@oai/artifact-tool` 运行时,他机不可复现。最低要求:将 `blind_samples.jsonl`、`sample_manifest.json`、模板 xlsx 的 SHA-256 记录进 Git(文件本身可不入库),与评估结果 commit `03c4701` 形成同级引用锚点。

## P2-2 语言一致性说明

scene_description 为英文(DriveLM 原文),其余为中文。若标注者英文阅读无碍则不必改;但需在说明页注明「scene_description 为数据集原文,仅作场景背景,判定证据以 structured_facts 与 trajectory_summary 为准」,避免标注者从英文叙述中过度推断。
